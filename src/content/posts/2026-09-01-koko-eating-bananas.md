Find the smallest constant eating speed that finishes every banana pile within a fixed number of hours.

## Problem

**Input.** A nonempty list `piles` of positive integers and an integer deadline `hours >= len(piles)`.

**Output.** Return the minimum positive integer speed, measured in bananas per hour, that finishes all piles by the deadline.

**Rules.** During one hour, work on only one pile and consume up to the chosen speed.
Finishing a smaller remainder still uses the whole hour; unused capacity cannot transfer to another pile.
Use one speed throughout and preserve the piles. The reference assumes a feasible deadline.

**Example.** Piles `[3, 6, 7, 11]` with 8 hours return `4`.
At that speed the piles take 1, 2, 2, and 3 hours, totaling 8.

At speed $s$, required time is $T(s)=\sum_i\lceil p_i/s\rceil$.
Each ceiling term is nonincreasing in $s$, giving a false-to-true feasibility boundary.
Under the reference contract, speed `max(piles)` is feasible: each pile needs one hour.
The minimum stays within `[left, right]`; an infeasible midpoint is removed, but a feasible midpoint remains a possible answer.

## Code

```python
def min_eating_speed(piles: list[int], hours: int) -> int:
   left, right = 1, max(piles)

   while left < right:
      speed = (left + right) // 2
      time = sum((pile + speed - 1) // speed for pile in piles)
      if time <= hours:
         right = speed
      else:
         left = speed + 1
   return left
```

The bounds meet at 4; speed 3 needs 10 hours, proving minimality rather than feasibility alone.
Integer ceiling division avoids floating-point rounding.
For $n$ piles and maximum $m$, there are $O(1+\log m)$ probes, each costing $O(n)$.
Auxiliary space is $O(1)$ under unit-cost arithmetic.

## Change 1: Expose Impossible and Empty Cases

**New task.** Return `None` when impossible and 0 when no piles exist.

**Picture and change.** Keep positive piles and a nonnegative integer deadline. Guard before calling the retained reference.

**Code.** Place this wrapper after `min_eating_speed`:

```python
def min_speed_or_none(piles, hours):
   if not piles:
      return 0
   if hours < len(piles):
      return None
   return min_eating_speed(piles, hours)
```

**Check.** Four piles with 3 hours return `None`; `([], 0)` returns 0; the main input returns 4.

**Use when.** The API accepts deadlines outside the guaranteed-feasible contract.

## Change 2: Add Fixed Per-Pile Setup

**New task.** Each pile also needs `setup` nonnegative integer hours, independent of speed.

**Picture and change.** Subtract total setup before the same monotone search. Retain the reference function above this wrapper.

**Code.**

```python
def min_speed_with_setup(piles, hours, setup):
   if not piles:
      return 0
   eating_hours = hours - setup * len(piles)
   if eating_hours < len(piles):
      return None
   return min_eating_speed(piles, eating_hours)
```

**Check.** Twelve hours minus four setup hours leaves eight: answer 4. For `[3, 6]`, 3 hours, setup 1, return `None`.

**Use when.** Added work changes feasibility without changing its monotone direction.

## Failure: Returning an Infeasible Upper Bound

Four positive piles need at least four hours. The unguarded reference does not solve a three-hour deadline.

### Reasoned Answer

Total time may cease to be monotone. Re-prove the boundary property and feasible bounds before reusing binary search.

## Preserve the First Feasible Candidate

Unlike exact index lookup, equality with the deadline does not settle minimality.
Setting `right = speed - 1` can discard the only minimum candidate; keep it with `right = speed`.
With `left < right`, the midpoint is strictly below `right`, so either branch shrinks the candidate interval.

Empty input would make the original `max([])` fail; impossibility can make it return an infeasible maximum.
The wrappers expand the output contract without changing the original function's guaranteed-feasible domain.
They rely on their stated input preconditions, not runtime validation of arbitrary objects.

This discrete scheduling model is not a real serving-latency or fleet-SLO guarantee.
Compare [candidate-interval search](/questions/binary-search/) when defining and proving new boundary contracts.
