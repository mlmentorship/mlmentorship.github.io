Report the number of binary one bits in every integer from zero through a given bound.

## Problem

**Input.** A nonnegative integer `limit`.

**Output.** Return a list of length `limit + 1`; entry `i` is the number of ones in `i`'s binary representation.

**Rules.** Include both endpoints, zero and `limit`, in increasing numeric order.
Leading zero bits do not affect the count. The binary representation of zero has no one bits.
Negative bounds are outside the contract.

**Example.** For `limit = 5`, return `[0, 1, 1, 2, 1, 2]`.
Entry 3 is 2 because binary `11` contains two ones. Bound zero returns `[0]`.

## Picture

Array index `value` names an integer, not a bit position. Its stored entry is that integer's population count.

The arrow points from the value being solved to its completed predecessor, `value >> 1`.

## Code

For nonnegative integers, right shift removes the low bit. The remaining integer is strictly smaller when `value > 0`.

`value & 1` is exactly the removed contribution: zero or one.

$$
	ext{answer}[\text{value}]
= \text{answer}[\text{value} \mathbin{\gg} 1] + (\text{value} \mathbin{\&} 1)
$$

```python
def count_bits(limit: int) -> list[int]:
   answer = [0] * (limit + 1)
   for value in range(1, limit + 1):
      answer[value] = answer[value >> 1] + (value & 1)
   return answer
```

### Why the Read Is Ready

Before each write, every lower-index answer is complete. The smaller predecessor therefore has its final count, not a provisional zero.

The explicit base is `answer[0] = 0`. Uncomputed cells also contain zero in memory, but the picture marks them `?` to distinguish unknown from solved.

For six, read `answer[3] = 2` and add its removed zero bit. The result is `[0,1,1,2,1,2,2]`.

### Output and Cost

The function performs `limit` writes and returns `limit + 1` integer slots. Under bounded-word arithmetic, time is $O(\text{limit})$.

Python's shifts and bit operations depend on operand width. Returning every answer cannot take only logarithmic output space.

Zero returns `[0]`. Negative limits are outside the reference contract.

**Recall:** What certifies a reusable predecessor? It is smaller, already solved, and differs by a known removed contribution.

## Remove a Whole Set Bit

**Choose this when:** The lowest-set-bit identity is the dependency you want to reuse.

[Number of 1 Bits](/questions/number-of-1-bits/) proves that `value & (value - 1)` removes exactly one one.

For positive values, that predecessor is smaller. Add one to its completed count.

```python
def count_bits_by_clear(limit):
   answer = [0] * (limit + 1)
   for value in range(1, limit + 1):
      answer[value] = answer[value & (value - 1)] + 1
   return answer
```

For six, this reads `answer[4] = 1` and adds one. The shift recurrence instead reads `answer[3] = 2` and adds zero.

Both return the same table, with the same nonnegative input contract and output-size bound. Their removed contributions differ because their predecessors differ.

## Return Only the Total

**Choose this when:** Only the sum of all counts from zero through `limit` is required.

Split at the highest power of two, $p=2^k$. The complete lower block `0..p-1` contains $k\,2^{k-1}$ ones when $k>0$.

Values `p..limit` contribute `limit - p + 1` leading ones. Their remaining low parts cover `0..limit-p`.

```python
def total_set_bits(limit):
   if limit <= 0:
      return 0
   exponent = limit.bit_length() - 1
   power = 1 << exponent
   full_block = exponent * (power >> 1)
   leading_ones = limit - power + 1
   return full_block + leading_ones + total_set_bits(limit - power)
```

For six, the lower block contributes four, leading ones contribute three, and the remainder contributes two. The total is nine.

Nonpositive input returns zero. At most $O(\log \text{limit})$ recursive levels are needed, but dense huge integers can reach Python's recursion limit.

Each frame holds width-dependent integers; bit costs are not constant. This smaller output contract avoids constructing a linear table.
