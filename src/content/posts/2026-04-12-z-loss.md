## Summary

Z-loss adds a term proportional to $(\log Z)^2$ to the cross-entropy objective, where $Z = \sum_v \exp(\ell_v)$ is the softmax partition function over the vocabulary and $\ell_v$ are the pre-softmax logits.

$$
\mathcal{L} = \mathcal{L}_{\text{CE}} + \lambda_z \cdot (\log Z)^2
$$

A typical coefficient is $\lambda_z = 10^{-4}$. The term encourages $\log Z$ to stay near zero, anchoring the common offset that cross-entropy leaves unconstrained. It does not bound every logit difference.

Two reasons, in order of how often they come up:

1. **Stability.** Without z-loss, large LLM training runs occasionally see the `lm_head` logits drift to very large magnitudes, which can cause numerical issues in the softmax (especially in BF16 or FP8). PaLM and DeepSeek both used z-loss for this.
2. **A controlled cooldown intervention.** The [Marin 8B retrospective](https://marin.readthedocs.io/en/latest/reports/marin-8b-retro/) reports a successful intervention in its recipe. Excluding normalization parameters from weight decay is an implementation choice, not proof that no other control exists. Z-loss anchors the common-offset direction; it does not bound every parameter norm or logit difference.

## The mechanism

The cross-entropy loss for a single token with target $y$ is:

$$
\mathcal{L}_{\text{CE}} = -\ell_y + \log Z
$$

Note that $\mathcal{L}_{\text{CE}}$ is invariant to adding a constant to all logits (because $\log Z$ shifts by the same amount that $\ell_y$ does). That invariance means cross-entropy alone provides no gradient pressure on the common offset of the logits. The model can drift the entire logit vector up or down without changing the loss.

Adding $\lambda_z (\log Z)^2$ breaks the invariance. The gradient with respect to a logit $\ell_v$ becomes:

$$
\frac{\partial \mathcal{L}}{\partial \ell_v} = (p_v - \mathbb{1}[v=y]) + 2 \lambda_z (\log Z) \cdot p_v
$$

The second term pulls $\log Z$ toward zero, anchoring the otherwise free common offset. The pressure is small per-step but persistent.

## When to use it

Consider a measured ablation when diagnostics indicate a relevant failure mode:

- Track log-partition values, logit differences, finite-value failures, and held-out task behavior rather than choosing from model size alone.
- Treat Marin's cooldown result and coefficient as a source-specific example to reproduce or test, not a universal prescription.
- Compare the actual low-precision implementation and a recoverable control run before attributing an instability to the common-offset direction.

Short fine-tuning and large pretraining both need a workload-specific decision; neither label settles whether the extra objective helps.

## How to set the coefficient

A coefficient such as $10^{-4}$ is a starting point for an ablation, not a scale-free guarantee of a small penalty.
For that coefficient, $\log Z=2$ contributes 0.0004, while $\log Z=100$ contributes one.
State token/batch reduction and log base: natural-log cross-entropy is measured in nats, not bits.
The [cross-entropy lesson](/concepts/cross-entropy-softmax/) separates the probability objective from added regularizers.

If you set $\lambda_z$ much larger, the model spends capacity matching $\log Z = 0$ instead of fitting the data and downstream perplexity worsens. If you set it much smaller, you lose the regularization effect.

## Subtle effects worth knowing

Subsequent Marin experiments showed that z-loss doesn't just prevent logit blowup. In the steady state, z-loss **increases** the weight norm of the `lm_head` and **decreases** the scale of the final layer norm. This makes sense in retrospect: the final layer norm has a disproportionate impact on logit scale (one parameter affecting all logits), and it's the only player not constrained by weight decay. Z-loss redistributes the pressure.

## What an interviewer expects you to say

If asked about z-loss:

1. State that it's a penalty on $(\log Z)^2$ added to cross-entropy.
2. Explain that cross-entropy is invariant to adding a constant to all logits, so it provides no gradient on absolute logit scale. Z-loss breaks that invariance.
3. Mention both use cases: stability against logit blowup and regularization on logit scale during deep cooldowns.
4. Inspect the actual decay groups and precision policy; explain why a source-specific intervention is not a bound on every logit or parameter.
