Find the longest run of consecutive integer values present anywhere in an unordered input list.

## Problem

**Input.** An unsorted integer list `nums`, possibly containing negatives and duplicates.

**Output.** Return the greatest number of distinct values in any run increasing by exactly one each time.

**Rules.** Values need not be adjacent or appear in increasing input order.
Repeated copies of a value do not extend a run. Return only the length, not the values or indices.
Do not change the input. Empty input returns zero.

**Example.** `[100, 4, 200, 1, 3, 2]` returns `4` for the run `1, 2, 3, 4`.
For `[1, 1, 2]`, return `2`, because the repeated 1 adds no new consecutive value.

Each distinct value gets one predecessor test. Each belongs to one expanded run; successful successor steps total $u-c$.
Here $u$ counts distinct values and $c$ counts maximal runs. Each run also ends with one failed successor query.
Thus all successor queries total $u$, not $u^2$, regardless of set iteration order.

## Code

```python
def longest_consecutive(nums: list[int]) -> int:
   values = set(nums)
   best = 0

   for start in values:
      if start - 1 in values:
         continue

      end = start
      while end + 1 in values:
         end += 1
      best = max(best, end - start + 1)

   return best
```

Expected time is $O(n)$, including set construction; space is $O(u)$, with $u\le n$.
This assumes expected constant-time hashing and ordinary integer arithmetic.

## Change 1: Return a Deterministic Witness

**New task.** Return run values, choosing the smallest start on ties.

**Picture and change.** Save length and start; materialize only the winner.

**Code.**

```python
def longest_run_values(nums):
   values = set(nums)
   best_start, best_length = None, 0
   for start in values:
      if start - 1 in values:
         continue
      end = start
      while end + 1 in values:
         end += 1
      length = end - start + 1
      if length > best_length or (length == best_length and start < best_start):
         best_start, best_length = start, length
   return [] if best_start is None else list(range(best_start, best_start + best_length))
```

**Check.** `[8, 9, 1, 2]` returns `[1, 2]`; empty input returns `[]`.

**Use when.** A reproducible witness matters. Its output storage is additional.

## Change 2: A Fixed Positive Integer Step

**New task.** Consecutive members differ by `step`, not necessarily 1.

**Picture and change.** Test `start-step`, advance `end+step`, and measure length in steps.

**Code.**

```python
def longest_fixed_step(nums, step):
   if step <= 0:
      raise ValueError("positive step required")
   values = set(nums)
   best = 0
   for start in values:
      if start - step in values:
         continue
      end = start
      while end + step in values:
         end += step
      best = max(best, (end - start) // step + 1)
   return best
```

**Check.** `[1, 3, 5, 2, 4]`, step 2, gives 3; `[-3, -1, 1]` also gives 3.
Step zero raises an error instead of invalidating progress.

**Use when.** A fixed successor spacing still partitions values into disjoint runs.

## Failure: Starting From Every Member

Expanding suffixes from every value of a length-$u$ run costs $u+(u-1)+\cdots+1$ work, which is quadratic.

## Transfer Check

Why do the nested loops not make the reference quadratic?

### Reasoned Answer

Only the unique start expands each disjoint run. Charge each successful advance to a distinct value, not every outer iteration.

## What Information Does the Set Discard?

It forgets input order and multiplicity, neither of which changes this length-only answer.
An adjacent-position requirement would be different: `[1, 3, 2]` contains value run `1, 2, 3`, not an adjacent increasing run.
That task needs positional information the set discarded.

The outer loop must use distinct values too. Repeating a run's head from the original duplicated input can rescan the same run.
The predecessor guard alone does not prevent those repeated-head scans.

The witness tie rule is needed only because the output now selects particular values.
The reference's maximum length does not depend on iteration order.
Fixed positive spacing preserves one predecessor and successor per integer, but a general graph can branch or cycle.
Do not transfer this start-only proof to arbitrary connected components without traversal and visited-state reasoning.
