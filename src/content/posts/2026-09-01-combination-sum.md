List the distinct value combinations that reach an exact target, allowing each positive candidate to be reused.

## Problem

**Input.** An integer list `candidates` and an integer `target`.

**Output.** Return every distinct combination of positive candidate values whose sum equals `target`.

**Rules.** Reuse is unlimited. Reordering the same values does not create a new combination.
The reference ignores duplicate and nonpositive candidates; it does not solve unrestricted signed combinations.
Leave the input unchanged. Target zero returns `[[]]`; a negative target returns `[]`.

**Example.** For `candidates = [2, 3, 6, 7]` and `target = 7`, return `[[2, 2, 3], [7]]`.
`[2, 3, 2]` is not an additional answer because it repeats the same value combination.

## Picture

For `[2,3,6,7]` and target seven:

| Path | `start` | `remaining` | Next action |
| --- | --- | --- | --- |
| `[]` | 0 | 7 | Choose 2 |
| `[2]` | 0 | 5 | Reuse 2 |
| `[2,2]` | 0 | 3 | Try 2, then 3 |
| `[2,2,2]` | 0 | 1 | Break because 2 is too large |
| `[2,2,3]` | 1 | 0 | Copy a solution |
| `[7]` | 3 | 0 | Copy the other solution |

Keep `sum(path) + remaining == target`. `start` is the lowest eligible choice index, not the path length.
Passing the **same** `index` permits another copy. Never decreasing it prevents reordered duplicates such as `[3,2,2]`.

Each positive choice strictly reduces `remaining`. Once a sorted choice exceeds the remainder, every later choice does too: break the loop.

Reuse [append, recurse, undo](/questions/subsets/). Pop after each recursive return, but copy a successful path before later mutations change it.

The call nodes show remaining targets; labels below them show `start`. Each arrow subtracts the chosen value.

## Code

```python
def combination_sum(candidates: list[int], target: int) -> list[list[int]]:
   choices = sorted({num for num in candidates if num > 0})
   answer: list[list[int]] = []
   path: list[int] = []

   def choose(start: int, remaining: int) -> None:
      if remaining == 0:
         answer.append(path.copy())
         return

      for index in range(start, len(choices)):
         num = choices[index]
         if num > remaining:
            break
         path.append(num)
         choose(index, remaining - num)
         path.pop()

   choose(0, target)
   return answer
```

**Cost:** Exponential time in the worst case and $O(target)$ call-stack space when the
smallest choice is 1.

For $N$ inputs and $U$ positive unique values, normalization costs expected $O(N+U\log(U+1))$.
With positive target, depth is at most $\lfloor target/\min(choices)\rfloor$ when choices exist.
Working storage includes those choices and the active path; retained output additionally stores every copied answer element.

## Change Reuse or the Answer Type

Start from `combination_sum`. Preserve the remainder invariant while making the changed multiplicity or output contract explicit.

1. **Consume each input position once.**

   **New task:** Values are finite occurrences, not reusable denominations.

   **Picture and change:** Keep duplicate positive occurrences. Recurse with `index + 1`, and skip equal siblings only at the same decision depth.
   Equal values at deeper indices can still be used together.

   **Code:** Complete replacement, retaining positive filtering:

   ```python
   def combination_sum_once(candidates, target):
      choices = sorted(value for value in candidates if value > 0)
      answer, path = [], []

      def choose(start, remaining):
         if remaining == 0:
            answer.append(path.copy())
            return
         for index in range(start, len(choices)):
            value = choices[index]
            if value > remaining:
               break
            if index > start and value == choices[index - 1]:
               continue
            path.append(value)
            choose(index + 1, remaining - value)
            path.pop()

      choose(0, target)
      return answer
   ```

   **Check:** `[2,2,3]`, target four gives `[[2,2]]`. `[2,3]`, target four gives `[]`, unlike unlimited reuse.

   **Use when:** Each occurrence is consumable. Depth is at most the number of positive positions, but enumeration and output can still be exponential.

2. **Count reusable combinations.**

   **New task:** Return only the number of value combinations.

   **Picture and change:** Initialize one empty construction at subtotal zero.
   Process denominations outside and subtotals upward: the current denomination may repeat, but earlier denominations cannot be reordered afterward.

   **Code:** Complete replacement:

   ```python
   def count_combinations(candidates, target):
      if target < 0:
         return 0
      counts = [0] * (target + 1)
      counts[0] = 1
      for value in sorted({value for value in candidates if value > 0}):
         for subtotal in range(value, target + 1):
            counts[subtotal] += counts[subtotal - value]
      return counts[target]
   ```

   **Check:** `[2,3,6,7]`, target seven gives two; target zero gives one. `[1,2]`, target three gives two, not three ordered sequences.

   **Use when:** Enumeration is unnecessary and target-sized storage is affordable.
   Beyond normalization, work is $O(U\cdot target)$ additions and storage is $O(target+U)$.
   This is pseudo-polynomial in numeric target. Exact counts can require increasingly large integers.

## Rebuild Eligibility

Does changing `index` to `index + 1` merely optimize the original search?

**Answer:** No. It removes that occurrence from future eligibility, changing unlimited reuse to single-use positions.
