Start one search for each group still uncovered. That search marks the entire group, so none of its other vertices starts another count.

## Problem

> Count separate groups in an undirected graph.

Use nonnegative `node_count` and valid integer endpoints `0..node_count-1`.
Every listed vertex exists even without edges. Zero vertices gives zero components; six vertices without edges gives six.

## Picture

With six nodes and edges `0-1`, `0-2`, `3-4`, the groups are `{0,1,2}`, `{3,4}`, and `{5}`.

| New start | After its flood | Later starts skipped |
| --- | --- | --- |
| 0 | `seen={0,1,2}`, `components=1` | 1 and 2 |
| 3 | `seen={0,1,2,3,4}`, `components=2` | 4 |
| 5 | `seen={0,1,2,3,4,5}`, `components=3` | None |

Node five still launches a flood. Its stack empties immediately because it has no neighbors.

This is [permanent component coverage](/questions/number-of-islands/) with explicit vertices instead of grid cells.
An unseen start cannot belong to a completed flood: that flood would have reached it.
Each launch therefore counts one new component, and its full coverage prevents double counting.

Mark a vertex before pushing it. `seen` means discovered, not fully expanded; a pending vertex must not be scheduled again.
The LIFO stack expands the first group in order `0,2,1`.

Duplicate edges and self-loops do not change these groups, but they still require scans.
Do not use this undirected flood to count directed strongly connected components.

## Code

```python
def count_components(node_count: int, edges: list[list[int]]) -> int:
   graph = [[] for _ in range(node_count)]
   for first, second in edges:
      graph[first].append(second)
      graph[second].append(first)

   seen: set[int] = set()
   components = 0
   for start in range(node_count):
      if start in seen:
         continue

      components += 1
      seen.add(start)
      stack = [start]
      while stack:
         for neighbor in graph[stack.pop()]:
            if neighbor not in seen:
               seen.add(neighbor)
               stack.append(neighbor)
   return components
```

Expected work is $O(V+E)$. Total storage is $O(V+E)$ for adjacency plus $O(V)$ for `seen` and the stack.

## Change the Component Summary

Start from `count_components`. Keep the same permanent marks and change what each completed flood contributes.

1. **Return group sizes.**

   **New task:** Return the cardinality of each component.

   **Picture and change:** Count one vertex per pop. Append the size only when that component's stack empties.

   **Code:** Complete replacement:

   ```python
   def component_sizes(node_count, edges):
      graph = [[] for _ in range(node_count)]
      for first, second in edges:
         graph[first].append(second)
         graph[second].append(first)
      seen, sizes = set(), []
      for start in range(node_count):
         if start in seen:
            continue
         seen.add(start)
         stack, size = [start], 0
         while stack:
            node = stack.pop()
            size += 1
            for neighbor in graph[node]:
               if neighbor not in seen:
                  seen.add(neighbor)
                  stack.append(neighbor)
         sizes.append(size)
      return sorted(sizes)
   ```

   **Check:** The example gives `[1,2,3]`, whose sum is six. With four isolated vertices, return `[1,1,1,1]`.

   **Use when:** Group-size distribution matters. Sorting stabilizes output, not connectivity. For $C$ components it adds $O(C\log(C+1))$ work to the flood.

2. **Count unreachable unordered pairs.**

   **New task:** Count vertex pairs lying in different components, without listing every pair.

   **Picture and change:** Remove a whole group's size from `remaining`, then pair that group with every still-unprocessed vertex.
   No vertex within the same component contributes. Every cross-component pair contributes when its earlier group is processed.

   **Code:** Uses `component_sizes` above:

   ```python
   def unreachable_pairs(node_count, edges):
      remaining, pairs = node_count, 0
      for size in component_sizes(node_count, edges):
         remaining -= size
         pairs += size * remaining
      return pairs
   ```

   **Check:** Sorted sizes `[1,2,3]` give $1\cdot5+2\cdot3+3\cdot0=11$. Four isolated vertices give six pairs.

   **Use when:** Connectivity supplies a combinatorial summary. This version inherits the helper's sorting cost and $O(V+E)$ total storage.

## Rebuild Coverage

Why is `seen` not restored after each component flood?

**Answer:** A reached vertex permanently belongs to that counted component. Unlike [Word Search](/questions/word-search/), marks are not temporary path exclusions.
