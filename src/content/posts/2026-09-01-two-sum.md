Return two distinct original indices whose values sum to the target.
Search earlier values for the needed partner, then save the current value after a miss.

## Problem

For `[3, 2, 4, 7]`, target 6, return `[1, 2]` because `2 + 4 == 6`.
Return any valid pair, not every pair or the values. No solution returns `[]`; duplicates are allowed.

Before each query, `seen` represents earlier values with strictly earlier indices.
One index per value suffices for one witness. Overwriting after a miss preserves that guarantee.
The trace's `i` is the code's `index`.

## Code

```python
def two_sum(nums: list[int], target: int) -> list[int]:
   seen: dict[int, int] = {}
   for index, num in enumerate(nums):
      needed = target - num
      if needed in seen:
         return [seen[needed], index]
      seen[num] = index
   return []
```

Expected time is $O(n)$ under usual dictionary/unit-cost arithmetic assumptions; auxiliary space is $O(n)$.

`[3]`, target 6, returns `[]`; `[3, 3]` returns `[0, 1]`.

## Change 1: Count Index Pairs

**New task.** Count distinct unordered index pairs.

**Picture and change.** Store prior frequencies; query before incrementing.

**Code.**

```python
def count_pairs(nums, target):
   counts = {}
   answer = 0
   for value in nums:
      answer += counts.get(target - value, 0)
      counts[value] = counts.get(value, 0) + 1
   return answer
```

**Check.** `[3, 3, 3]`, target 6, adds 0, 1, 2: total 3. A single 3 gives 0.

**Use when.** Multiplicity matters without emitting indices.

## Change 2: Emit Every Pair

**New task.** Return all original-index witnesses.

**Picture and change.** Keep every earlier matching index, not one representative.

**Code.**

```python
def all_pairs(nums, target):
   seen = {}
   answer = []
   for index, value in enumerate(nums):
      for earlier in seen.get(target - value, []):
         answer.append([earlier, index])
      seen.setdefault(value, []).append(index)
   return answer
```

**Check.** `[3, 3, 3]`, target 6, returns `[[0, 1], [0, 2], [1, 2]]`.

**Use when.** Every witness is required.

## Failure: Saving Before Querying

Store-first logic lets the lone 3 in `[3]` match itself. Query order enforces distinctness.

## Transfer Check

Why may the reference overwrite repeated values but `all_pairs` may not?

### Reasoned Answer

One earlier witness suffices for the reference. Enumeration must retain every matching position.

## Output Size Changes the Cost

The counting variant retains expected $O(n)$ time and $O(n)$ auxiliary space.
For $m$ returned pairs, enumeration takes expected $O(n+m)$ time and $O(n+m)$ total space, including output.
All-equal input can produce $n(n-1)/2$ pairs; no algorithm can materialize them in linear output space.

Empty input yields no witness, zero count and an empty enumeration.
Sorting changes position tracking and needs a different movement proof; it is not a drop-in replacement for this contract.
Compare [prefix counting](/questions/subarray-sum-equals-k/) when stored objects become range boundaries rather than item positions.
