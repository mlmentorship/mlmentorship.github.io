Find the minimum number of single-character edits needed to transform one complete string into another.

## Problem

**Input.** Two Python strings, `first` and `second`.

**Output.** Return the smallest edit count that changes `first` into exactly `second`.

**Rules.** Inserting, deleting, or replacing one character costs one; keeping an equal character costs zero.
Swapping adjacent characters is not a separate allowed edit.
Characters are Python code points without automatic normalization. Preserve both strings.
Return a distance, not an edit script or semantic similarity score.

**Example.** `"horse"` to `"ros"` returns `3`: replace `h`, delete the extra `r`, then delete `e`.
Changing `""` into `"cat"` costs `3` insertions.

## Picture

Let `D[i,j]` be the minimum edits from `first[:i]` to `second[:j]`.
The two-prefix layout matches [LCS](/questions/longest-common-subsequence/), but this objective minimizes transformation cost, not maximizes kept length.

Undo the final operation to find its predecessor:

| Final operation | Already-solved cost | Direction into current cell |
| --- | --- | --- |
| Insert `second[j-1]` | `D[i,j-1]`, then add one | Left |
| Delete `first[i-1]` | `D[i-1,j]`, then add one | Above |
| Replace unequal endpoints | `D[i-1,j-1]`, then add one | Diagonal |
| Keep equal endpoints | `D[i-1,j-1]`, no new cost | Diagonal |

These cases cover the final alignment step. Choosing the cheapest predecessor plus its operation cost gives the optimum.
Empty-to-prefix borders cost `j` insertions; prefix-to-empty borders cost `i` deletions.

For `cat` to `cut`, the rows are:

| First prefix | Costs to `""`, `c`, `cu`, `cut` |
| --- | --- |
| `""` | `[0,1,2,3]` |
| `c` | `[1,0,1,2]` |
| `ca` | `[2,1,1,2]` |
| `cat` | `[3,2,2,1]` |

At `ca` to `cu`, predecessor costs are insert one, delete one and replace zero. Replacement therefore costs one.
The final equal `t` copies that diagonal answer. Distance is one, from replacing `a` with `u`.

Before appending column `j`, `previous[j]` is above, `previous[j-1]` is diagonal, and `current[-1]` is left.
All are final. Commit `previous = current` only after completing the row.
In the visual, `Q` is the current cell; `I/D/R` identify those operation predecessors.

## Code

```python
def edit_distance(first: str, second: str) -> int:
   previous = list(range(len(second) + 1))

   for first_index, first_char in enumerate(first, 1):
      current = [first_index]
      for second_index, second_char in enumerate(second, 1):
         if first_char == second_char:
            current.append(previous[second_index - 1])
         else:
            insert = current[-1]
            delete = previous[second_index]
            replace = previous[second_index - 1]
            current.append(1 + min(insert, delete, replace))
      previous = current

   return previous[-1]
```

**Cost:** For lengths $m,n$, $O(mn+m+n)$ work includes empty-border handling; row storage is $O(n+1)$ slots.
Unit-cost symmetry permits swapping strings to store the shorter axis. The source does not perform that swap.
Recovering an edit script needs additional reconstruction state or another algorithm.

## Change Operation Prices or Eligibility

Start from `edit_distance`. Keep the prefix meaning and row dependencies, but change each transition together with its border prices.

1. **Use different operation costs.**

   **New task:** Minimize nonnegative insertion, deletion and replacement prices rather than operation count.

   **Picture and change:** Charge each edge separately. Empty-to-prefix uses insertion prices; prefix-to-empty uses deletion prices.
   Compare all transitions, with zero diagonal cost for equal characters.

   **Code:** Complete replacement. Costs must be finite and nonnegative:

   ```python
   def weighted_edit_distance(first, second, insert_cost, delete_cost, replace_cost):
      previous = [index * insert_cost for index in range(len(second) + 1)]
      for first_index, first_char in enumerate(first, 1):
         current = [first_index * delete_cost]
         for second_index, second_char in enumerate(second, 1):
            current.append(min(
               current[-1] + insert_cost,
               previous[second_index] + delete_cost,
               previous[second_index - 1] + (
                  0 if first_char == second_char else replace_cost
               ),
            ))
         previous = current
      return previous[-1]
   ```

   **Check:** `a` to `b`, prices `(1,1,3)`, costs two: delete then insert beats replacement.
   Empty to `ab`, prices `(2,5,1)`, costs four, not two.

   **Use when:** Prices change while eligible edits stay the same.
   Time and row-slot bounds remain unchanged, excluding numeric bit costs.

2. **Forbid replacement.**

   **New task:** Permit insertion and deletion only.

   **Picture and change:** Remove the mismatch diagonal alternative. Equal endpoints still match for free; borders stay unit-priced.

   **Code:** Complete replacement:

   ```python
   def insert_delete_distance(first, second):
      previous = list(range(len(second) + 1))
      for first_index, first_char in enumerate(first, 1):
         current = [first_index]
         for second_index, second_char in enumerate(second, 1):
            if first_char == second_char:
               current.append(previous[second_index - 1])
            else:
               current.append(1 + min(current[-1], previous[second_index]))
         previous = current
      return previous[-1]
   ```

   **Check:** `cat` to `cut` now costs two, as does `a` to `b`.
   This operation set satisfies $m+n-2\cdot LCS(first,second)$, unlike replacement-enabled distance.

   **Use when:** Operation eligibility changes. The original row bounds still apply.

What must change when swapping strings with asymmetric prices?
