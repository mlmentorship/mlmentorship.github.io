Choose nonadjacent houses around a circle to maximize the total value collected.

## Problem

**Input.** A list `nums` of nonnegative integer house values in circular order.

**Output.** Return the largest sum obtainable by selecting houses without selecting any adjacent pair.

**Rules.** The first and last houses are neighbors, as are consecutive positions.
Taking no houses is allowed. Preserve the input.
Empty input returns zero; a single house may be selected without conflicting with itself.

**Example.** `[2, 3, 2]` returns `3`, not `4`, because the two endpoint houses are neighbors.
For `[1, 2, 3, 1]`, return `4` by selecting values 1 and 3 at indices 0 and 2.

## Picture

For `[1,2,3,1]`, the wraparound edge forbids selecting indices zero and three together.

| Case | Original indices | Prefix optima | Result |
| --- | --- | --- | --- |
| A: exclude last | `0,1,2` | `1,2,4` | 4, using indices `0,2` |
| B: exclude first | `1,2,3` | `2,3,3` | 3 |

Each valid circular plan appears in at least one case. Each case's linear solution also satisfies the circle.
Their maximum therefore equals the circular optimum.

The cases overlap: a plan omitting both endpoints belongs to both. The maximum ignores repeated candidates.
Adding case counts would double-count them.

Reuse the [linear prefix optimum](/questions/house-robber/).
Before each house, `one_back` is the optimum through the previous prefix; `two_back` is the optimum before that prefix's last house.
Neither variable says its last house was chosen.

Take the current value plus old `two_back`, or skip it and keep old `one_back`.
Update simultaneously and reset both states between cases.

Nodes show `index:value`. An `X` marks the excluded endpoint; its incident edges are absent.

Check `[2,3,2]`: linear selection would take both twos for four, but the circular answer is three.

## Code

```python
def house_robber_two(nums: list[int]) -> int:
   def rob(line: list[int]) -> int:
      two_back = one_back = 0
      for money in line:
         two_back, one_back = one_back, max(one_back, two_back + money)
      return one_back

   if len(nums) == 1:
      return nums[0]
   return max(rob(nums[:-1]), rob(nums[1:]))
```

**Cost:** $O(n)$ time and $O(n)$ space from the two slices. Index ranges can reduce extra
space to $O(1)$.

The slices are evaluated sequentially, but peak extra storage is still linear.
Negative values are outside this contract: a negative singleton would return that negative value rather than choosing none.

## Change Storage or Retain a Plan

Start from `house_robber_two`. Both adaptations keep the same two-case coverage proof.

1. **Avoid copied slices.**

   **New task:** Keep constant auxiliary slots.

   **Picture and change:** Pass half-open original-index ranges to the rolling recurrence. Neither pass constructs a sublist.

   **Code:** Complete replacement:

   ```python
   def circular_rob_ranges(nums):
      def rob_range(start, end):
         two_back = one_back = 0
         for index in range(start, end):
            two_back, one_back = one_back, max(one_back, two_back + nums[index])
         return one_back

      if len(nums) <= 1:
         return nums[0] if nums else 0
      return max(rob_range(0, len(nums) - 1), rob_range(1, len(nums)))
   ```

   **Check:** `[2,3,2]` returns three. Empty input returns zero. The original values stay unchanged.

   **Use when:** Memory is constrained. Work remains $O(n)$; auxiliary state is $O(1)$ slots.

2. **Return selected original indices.**

   **New task:** Retain a feasible plan achieving the scalar optimum.

   **Picture and change:** Save each line's prefix values. Backtrack: equal adjacent prefix values permit skipping; a strict improvement takes the current index.

   **Code:** Complete replacement:

   ```python
   def circular_rob_plan(nums):
      def line_plan(start, end):
         best = [0] * (end - start + 1)
         for offset in range(1, len(best)):
            before_neighbor = best[offset - 2] if offset > 1 else 0
            best[offset] = max(
               best[offset - 1], before_neighbor + nums[start + offset - 1]
            )
         selected, offset = [], len(best) - 1
         while offset > 0:
            if best[offset] == best[offset - 1]:
               offset -= 1
            else:
               selected.append(start + offset - 1)
               offset -= 2
         return best[-1], list(reversed(selected))

      if len(nums) <= 1:
         return [0] if nums and nums[0] > 0 else []
      first = line_plan(0, len(nums) - 1)
      second = line_plan(1, len(nums))
      return first[1] if first[0] >= second[0] else second[1]
   ```

   **Check:** `[1,2,3,1]` returns `[0,2]`; `[2,3,2]` returns `[1]`. Zero-valued ties may select nothing.

   **Use when:** A value alone is insufficient. Prefix history and reconstruction use $O(n)$ storage and work.
   Ties skip the current house within a line and prefer case A between lines; no unique-optimum claim is implied.

## Rebuild Case Coverage

Why combine these overlapping cases by `max`, not automatically by addition?

**Answer:** An optimum needs one best feasible candidate. Counting requires disjoint cases or an explicit overlap correction.
