Determine whether a list contains equal values at two different input positions.

## Problem

**Input.** A list `nums` of hashable integers, possibly empty.

**Output.** Return `True` if any integer appears at least twice; otherwise return `False`.

**Rules.** Repeated values count even when their positions are not adjacent.
Return existence, not a repeated value, its positions, or its number of occurrences.
Leave the list unchanged. Empty and singleton lists return `False`.

**Example.** `[1, 2, 3, 1]` returns `True` because positions 0 and 3 both contain 1.
For `[1, 2, 3]`, return `False`.

## Picture

Four input positions feed a set that keeps only distinct values:

| Consumed prefix | Set entries | Set size |
| --- | --- | --- |
| Empty | `{}` | 0 |
| `4` | `{4}` | 1 |
| `4,1` | `{4,1}` | 2 |
| `4,1,4` | `{4,1}` | 2 |
| `4,1,4,2` | `{4,1,2}` | 3 |

The second `4` adds no entry. The reference still consumes `2` before comparing lengths.

After each consumed prefix, the set contains exactly its distinct values. Inserting a new value adds one entry; inserting an equal value changes nothing.

The final input length is four, but the set size is three. The lost entry proves that two positions supplied equal values.

`len(nums)` counts input positions. `len(set(nums))` counts distinct values. Their inequality answers existence, not frequency or distance.

Entry order in the picture is not a set-order guarantee.

## Code

```python
def contains_duplicate(nums: list[int]) -> bool:
   return len(nums) != len(set(nums))
```

For $n$ values and $u$ distinct values, expected hashing work is $O(n)$ with $O(u)$ stored entries.
This assumes constant-cost hashing and equality, not an adversarial worst-case guarantee.

## Change What Must Survive

Adjust two parts of `contains_duplicate`: consumption and evidence.

1. **Stop before consuming the whole input.**

   **New task:** Detect a duplicate in an iterator and leave later values unconsumed.

   **Picture and change:** Replace whole-set construction with membership checks before insertion. Before each check, `seen` contains only earlier values.

   **Code:** This complete replacement accepts an iterable of hashable values.

   ```python
   def duplicate_in_stream(values):
      seen = set()
      for value in values:
         if value in seen:
            return True
         seen.add(value)
      return False
   ```

   **Check:** For iterator `4,1,4,2`, the second `4` returns `True`. The next unconsumed value is `2`.

   Inserting before checking would mistake the current value for an earlier occurrence. Without a collision, consume to exhaustion.

   **Use when:** Early stopping or iterator consumption matters. Expected work is linear in consumed values; memory grows with distinct values.

2. **Require a maximum index gap.**

   **New task:** Equal values count only when their distinct indices differ by at most integer `max_gap`.

   **Picture and change:** Replace membership with each value's latest index. Among earlier equal values, the latest gives the smallest gap.

   **Code:** This complete replacement preserves the input.

   ```python
   def nearby_duplicate(nums, max_gap):
      latest = {}
      for index, value in enumerate(nums):
         if value in latest and index - latest[value] <= max_gap:
            return True
         latest[value] = index
      return False
   ```

   **Check:** `[1,2,1]` returns `False` for gap one and `True` for gap two. Nonpositive gaps admit no pair.

   For `[1,2,1,1]`, updating `latest[1]` at index two lets index three succeed with gap one.

   **Use when:** A locality condition makes positions necessary. Expected time is $O(n)$ and stored entries are $O(u)$.

## Rebuild the Reason

Why can the gap variant discard older equal positions?

**Answer:** They are farther from every future index than the latest occurrence. If the latest is too far, older ones also fail.

Sets discard frequencies. An unbounded distinct stream can also require unbounded memory.
