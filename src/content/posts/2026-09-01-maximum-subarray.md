Find the largest sum obtainable from one nonempty contiguous range of an integer list.

## Problem

**Input.** A nonempty list `nums` of integers, including possible negative values and zeros.

**Output.** Return the largest sum over all nonempty contiguous subarrays.

**Rules.** At least one value must be selected. Skipping an interior position or returning an empty zero-sum selection is forbidden.
Return the sum, not its endpoints. Leave the list unchanged; empty input is outside the contract.

**Example.** `[-2, 1, -3, 4, -1, 2, 1, -5, 4]` returns `6` from `[4, -1, 2, 1]`.
For `[-3, -1, -2]`, return `-1`, not zero.

## Picture

`current` must end at the scan position. `best` may end earlier.

The start pointer belongs to the current range. The underline marks the saved best range, whose half-open boundaries appear below the row.

## Code

Every nonempty range ending here is either the current singleton or a prior-ending range extended by this value.

Addition preserves order, so only the largest prior-ending sum is needed. A negative carried sum makes restarting better; a positive one makes extension better.

$$
\begin{aligned}
	ext{current} &\leftarrow \max(\text{num},\ \text{current} + \text{num}) \\
	ext{best} &\leftarrow \max(\text{best},\ \text{current})
\end{aligned}
$$

```python
def max_subarray(nums: list[int]) -> int:
   current = best = nums[0]
   for num in nums[1:]:
      current = max(num, current + num)
      best = max(best, current)
   return best
```

### Keep the Two States Separate

For `[-2,1,-3,4,-1,2,1,-5,4]`, restart at `1`, then later at `4`.

Extending `[4,-1,2,1]` gives `current = best = 6` over `nums[3:7]`.

The next two current sums are `1` and `5`. Neither replaces the saved best of six.

Initialize both states from `nums[0]`, not zero. Otherwise an empty range could incorrectly beat every nonempty range on negative input.

For `[-4,-2]`, the answer is `-2`. Empty input is outside the reference contract and raises `IndexError`.

### Cost

With constant-cost integer arithmetic, time is $O(n)$. The literal reference uses $O(n)$ auxiliary space because `nums[1:]` copies the suffix.

The recurrence itself needs two scalar slots. Index iteration avoids the copy, as the first adaptation shows. The input is not modified.

**Recall:** Why retain only one prior-ending sum? Adding the same next value preserves order, so a smaller prior sum cannot win.

## Return a Witness Range

**Choose this when:** The answer must identify the interval, not just its sum.

Save the current start on restart. Copy its boundaries only when the global best strictly improves.

```python
def maximum_sum_range(nums):
   current = best = nums[0]
   current_start = best_start = 0
   best_end = 1
   for index in range(1, len(nums)):
      if nums[index] > current + nums[index]:
         current, current_start = nums[index], index
      else:
         current += nums[index]
      if current > best:
         best, best_start, best_end = current, current_start, index + 1
   return [best, best_start, best_end]
```

The example returns `[6,3,7]`, meaning sum six from `nums[3:7]`.

Equal sums keep the previously saved range. An extend/restart tie keeps the earlier start. This returns one deterministic witness, not every optimum.

Empty input raises `IndexError`. No input slice is allocated. With constant-cost arithmetic, time is $O(n)$ and auxiliary space is $O(1)$.

## Use a Prior Minimum Prefix

**Choose this when:** The next problem is easier to express as a difference between prefix sums.

Let $P[j]$ sum the first $j$ values. A nonempty interval has sum $P[j]-P[i]$ with $i<j$.

For each right boundary, subtract the smallest strictly earlier prefix. Score the candidate before admitting the current prefix as a future left boundary.

```python
def maximum_sum_by_prefix(nums):
   if not nums:
      raise ValueError("nonempty input required")
   total = minimum_prefix = 0
   best = nums[0]
   for value in nums:
      total += value
      best = max(best, total - minimum_prefix)
      minimum_prefix = min(minimum_prefix, total)
   return best
```

Updating the minimum first permits subtracting a prefix from itself. That admits an empty interval of sum zero and breaks all-negative input.

This adaptation rejects empty input explicitly. With constant-cost arithmetic, time is $O(n)$ and auxiliary space is $O(1)$. Both adaptations leave the input unchanged.

## Transfer

For a maximum product, a negative multiplier reverses preference. The prior minimum can become the next maximum, so one carried extreme is no longer enough.
