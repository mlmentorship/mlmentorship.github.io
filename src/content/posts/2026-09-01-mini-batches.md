Divide an ordered collection into consecutive batches without dropping, duplicating, or reordering any item.

## Problem

**Input.** A finite Python list `items` and a positive integer `batch_size`.

**Output.** Yield consecutive list batches, each with at most `batch_size` items, until every input occurrence has been yielded.

**Rules.** Preserve order. The final batch may be shorter and must not be discarded or padded.
Do not mutate the input. List slices copy references, not the referenced objects.
Empty input yields no batches. Nonpositive batch sizes are outside the contract.

**Example.** Items `[0, 1, 2, 3, 4]` with batch size 2 yield `[0, 1]`, then `[2, 3]`, then `[4]`.
With batch size 8, yield one batch containing all five items.

## Picture

Seven examples with size three use starts `0,3,6` and clipped stops `3,6,7`.
Every position belongs to exactly one half-open slice.

Advancing by the full batch size creates neither gaps nor duplicate positions.
Only the final slice may be short.

## Code

```python
from collections.abc import Iterator, Sequence

def batches(items: Sequence, batch_size: int) -> Iterator[Sequence]:
   if batch_size <= 0:
      raise ValueError("batch_size must be positive")
   for start in range(0, len(items), batch_size):
      yield items[start : start + batch_size]
```

**Cost:** $O(n)$ copied references overall; one yielded list needs $O(\min(n, batch\_size))$ storage.
Retaining all batches takes $O(n)$ storage.
Validation runs when the generator advances, not when it is created.

## Change the Requirement

### Discard a Short Tail

**New task:** Yield full-width batches only.

**Picture and change:** Stop before a start whose full end exceeds the input length.

**Code:** Use the reference imports above.

```python
def full_batches(items: Sequence, batch_size: int) -> Iterator[Sequence]:
   if batch_size <= 0:
      raise ValueError("batch_size must be positive")
   for start in range(0, len(items) - batch_size + 1, batch_size):
      yield items[start : start + batch_size]
```

**Check:** `list(full_batches(list(range(7)), 3))` returns `[[0,1,2], [3,4,5]]`.

**Use when:** A consumer explicitly requires fixed-width batches.

### Accept a One-Pass Source

**New task:** Batch an iterable without indexing or a known length.

**Picture and change:** Consume at most one batch from the iterator at each step.

**Code:** This complete generator retains the short tail.

```python
from collections.abc import Iterable
from itertools import islice

def stream_batches(items: Iterable, batch_size: int) -> Iterator[list]:
   if batch_size <= 0:
      raise ValueError("batch_size must be positive")
   iterator = iter(items)
   while batch := list(islice(iterator, batch_size)):
      yield batch
```

**Check:** `list(stream_batches(iter([1,2,3]), 2))` returns `[[1,2], [3]]`.

**Use when:** The source is one-pass or unbounded.
Memory tracks one batch, excluding consumer retention.

## Reconstruct

Why not average batch means equally when estimating the overall mean?

<details>
<summary>Reasoned answer</summary>

For batches `[0,0]` and `[9]`, the unweighted batch-mean average is `4.5`, but the example mean is `3`.
Weight each batch mean by its actual batch length.
The short tail represents fewer observations, not fewer valid examples.

The reference annotation permits other `Sequence` implementations, but their indexing, slicing, copying, and view semantics may differ.
The stated copying bounds and independent batch-container behavior apply to Python lists.
