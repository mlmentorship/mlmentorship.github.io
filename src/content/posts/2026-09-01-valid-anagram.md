Forget positions, but retain how often each character occurs.
Two strings are anagrams exactly when every character count matches.

## Problem

`"aab"` and `"aba"` return `True`; `"aab"` and `"abb"` return `False`.
The reference compares exact Python string code points, including case and whitespace. Two empty strings match.

After each prefix, its map records exactly the occurrences read so far.
Different counts leave some occurrences unmatched. Equal counts let every occurrence pair with the same character, regardless of position.
No position information is needed for this output.

## Code

```python
from collections import Counter

def is_anagram(first: str, second: str) -> bool:
   return Counter(first) == Counter(second)
```

Expected time is $O(n+m)$ for both string lengths; space is $O(k)$ for distinct code points across them.
These bounds assume ordinary hash-table costs.

## Change 1: Supply May Contain Surplus

**New task.** Can `supply` provide every character in `required`?

**Picture and change.** Keep counts but compare required multiplicities against available ones. Extra supply is now allowed.

**Code.**

```python
from collections import Counter

def can_construct(required, supply):
   available = Counter(supply)
   return all(available[character] >= count
            for character, count in Counter(required).items())
```

**Check.** `("aab", "baaac")` is `True`; `("aab", "ab")` is `False`; empty requirements always pass.

**Use when.** The contract is containment, not equality.

## Change 2: Declare a Text-Equivalence Policy

**New task.** Ignore case and canonical Unicode composition differences.

**Picture and change.** Apply `casefold`, then NFC normalization, before counting. This deliberately changes the exact reference.

**Code.**

```python
from collections import Counter
from unicodedata import normalize

def is_anagram_folded(first, second):
   left = normalize("NFC", first.casefold())
   right = normalize("NFC", second.casefold())
   return Counter(left) == Counter(right)
```

**Check.** `("Tea", "EAT")` passes. `("\u00e9", "e\u0301")` also passes here but fails the exact reference.

**Use when.** The application explicitly selects this equivalence; it is not universal linguistic equality.

## Failure: Replacing Counts With a Set

`"aab"` and `"abb"` have equal lengths and equal sets, but different multiplicities. A set loses the deciding information.

## Transfer Check

Why can equal total lengths not replace the maps?

### Reasoned Answer

Length fixes only the sum of counts. Different allocations among characters can have the same sum.

## Code Points Are Not Always Visible Characters

`"\u00e9"` contains one precomposed code point; `"e\u0301"` contains a letter and a combining mark.
Their visible forms can look alike while their exact counters differ.
Case folding can also change length: `"\u00df"` folds to `"ss"`.

The normalized variant defines equality after a specific transformation sequence.
It does not remove punctuation, ignore accents, or implement locale-specific or grapheme-cluster policies.
Those would be further task changes requiring explicit definitions and tests.

Counter construction explains the reference's expected linear bound.
Normalization adds transformation work and storage; do not silently attribute only counter costs to that variant.
The [grouping application](/questions/group-anagrams/) reuses exact multiplicities as bucket keys under its own alphabet contract.
