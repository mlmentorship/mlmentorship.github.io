Find every distinct combination of three input values whose sum is zero.

## Problem

**Input.** A list of integers `nums`, possibly containing negatives and repeated values.

**Output.** Return all distinct value triples whose sum is zero, not triples of indices.

**Rules.** Each triple must use three distinct input positions.
Repeated values are allowed when enough positions contain them.
Do not repeat a value combination; the order of returned triples does not matter.
The reference may reorder `nums` in place. Fewer than three values return `[]`.

**Example.** `[-1, 0, 1, 2, -1, -4]` returns `[[-1, -1, 2], [-1, 0, 1]]`.
The two copies of -1 occupy different positions. `[0, 0, 0, 0]` returns only `[[0, 0, 0]]`.

Sorted input is `[-4, -1, -1, 0, 1, 2]`. The trace's fixed `i`, `L`, `R` correspond to `index`, `left`, `right`.

| Fixed value | Pair totals/results |
| --- | --- |
| -4 | Totals -3, -3, -2, -1; exhaust the pair interval |
| First -1 | Emit `[-1, -1, 2]`, then `[-1, 0, 1]` |
| Second -1 | Skip repeated fixed value |
| 0 | Total 3 is too high; no result |

If the total is low even with the largest remaining right partner, no solution can use the current left value.
Symmetrically, a high total with the smallest remaining left partner rules out the current right value.
Each move preserves all unreported value triples; pointer crossing exhausts that fixed value.

Skip repeated fixed values. After a hit, skip copies of its successful left value: its required right value is already determined.

## Code

```python
def three_sum(nums: list[int]) -> list[list[int]]:
   nums.sort()
   answer: list[list[int]] = []

   for index, first in enumerate(nums):
      if index > 0 and first == nums[index - 1]:
         continue

      left, right = index + 1, len(nums) - 1
      while left < right:
         total = first + nums[left] + nums[right]
         if total < 0:
            left += 1
         elif total > 0:
            right -= 1
         else:
            answer.append([first, nums[left], nums[right]])
            left += 1
            right -= 1
            while left < right and nums[left] == nums[left - 1]:
               left += 1

   return answer
```

Pair work is $O(n^2)$ under ordinary comparison/arithmetic costs.
Python sorting can use $O(n)$ temporary workspace; $m$ emitted triples need $O(m)$ output space.
The pointer scan alone uses constant state, not the whole implementation.

## Change 1: Change the Target

**New task.** Return unique triples summing to any target.

**Picture and change.** Compare every total with `target`; preserve sorted elimination and duplicate rules.

**Code.** This replacement uses a sorted copy:

```python
def three_sum_target(nums, target):
   values = sorted(nums)
   answer = []
   for index, first in enumerate(values):
      if index and first == values[index - 1]:
         continue
      left, right = index + 1, len(values) - 1
      while left < right:
         total = first + values[left] + values[right]
         if total < target:
            left += 1
         elif total > target:
            right -= 1
         else:
            answer.append([first, values[left], values[right]])
            left += 1
            right -= 1
            while left < right and values[left] == values[left - 1]:
               left += 1
   return answer
```

**Check.** `[1, 2, 2, 3, 4]`, target 7, returns `[[1, 2, 4], [2, 2, 3]]`.

**Use when.** The equation changes, not the ordered elimination proof.

## Failure: Confusing Values With Indices

`[0, 0, 0, 0]` returns one value triple, not four index combinations.

## Transfer Check

Why is advancing `left` safe after a low total?

### Reasoned Answer

The current right value is already the largest available partner. Any smaller partner makes this left value no better.

## Why Duplicate Skipping Preserves Completeness

For fixed `first` and left value, the required right value is uniquely determined by the sum equation.
More positions containing those same values cannot create a new value triple.
For a new fixed value, the two-pointer scan starts over its entire remaining suffix.

The reference mutates with `nums.sort()`; the target variant uses `sorted(nums)` and the preservation wrapper copies first.
Test both output and input state. A correct result alone does not establish mutation compliance.

Returning original index triples would require different tracking and output-size accounting.
See [Two Sum](/questions/two-sum/) for an index-witness contract; its one-index map does not enumerate unique three-value results automatically.
