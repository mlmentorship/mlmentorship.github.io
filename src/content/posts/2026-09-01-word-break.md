A boundary is reachable only when the entire preceding prefix can be segmented; isolated dictionary matches do not suffice.

## Problem

Can `catsandog` be covered completely using `["cats","dog","sand","and","cat"]`?
Words may be reused; characters cannot be skipped or overlapped between tokens.
Matching uses exact Python strings, without normalization or fuzzy matches.
Return existence, not the number of possible parses.

## Picture

Boundary `0` sits before the first character; boundary `9` sits after the last.
Seed `0` because the empty prefix needs no words.
At a reachable start, an exact word match proves its ending boundary reachable.
Positive-length words point forward, so increasing start order processes each dependency before its consumer.

| Proven start | Matching word | New ending boundary |
| --- | --- | --- |
| `0` | `cats` | `4` |
| `0` | `cat` | `3` |
| `3` | `sand` | `7` |
| `4` | `and` | `7` again |

Boundary `7` leaves suffix `og`, not `dog`.
The final set is `{0,3,4,7}`, so boundary `9` remains unreachable.
Changing the text to `catsanddog` permits `cats + and + dog`.
Repeated discoveries collapse because the state asks existence, not multiplicity.

## Code

```python
def word_break(text: str, words: list[str]) -> bool:
   reachable = {0}
   for start in range(len(text) + 1):
      if start not in reachable:
         continue
      for word in words:
         if text.startswith(word, start):
            reachable.add(start + len(word))
   return len(text) in reachable
```

Empty text succeeds even with no tokens.
Empty tokens add self-loops but do not change Boolean reachability.
Duplicate dictionary entries repeat work without changing the answer.

With $n$ characters and $m$ entries, the reference performs at most $(n+1)m$ prefix tests.
Each costs $O(k+1)$ for maximum token length $k$; scanning and reachable storage cost $O(n+1)$.

## Change to One Segmentation Witness

**New task:** Return words covering the text, or `None` if impossible.

**Picture and change:** Save a parent boundary and word on first discovery, then follow parents backward and reverse.

```python
def word_break_witness(text, words):
   parent = {0: None}
   for start in range(len(text) + 1):
      if start not in parent:
         continue
      for word in words:
         end = start + len(word)
         if word and end not in parent and text.startswith(word, start):
            parent[end] = start, word
   if len(text) not in parent:
      return None
   answer, end = [], len(text)
   while end:
      end, word = parent[end]
      answer.append(word)
   return answer[::-1]
```

**Check:** `"leetcode"` and `["leet","code"]` return `["leet","code"]`; `"x"` with `["a"]` returns `None`.
Empty text returns `[]`.
Every selected token is nonempty, so parent boundaries strictly decrease during reconstruction.
First discovery does not promise the fewest words.

**Use when:** A Boolean answer needs inspectable evidence.

## Change to Parse Counts

**New task:** Count distinct token sequences, treating duplicate dictionary strings as the same token.

**Picture and change:** Seed one empty parse, then add every matching predecessor's count instead of collapsing endpoints.

```python
def segmentation_count(text, words):
   tokens = sorted(set(words) - {""})
   counts = [0] * (len(text) + 1)
   counts[0] = 1
   for start in range(len(text)):
      for word in tokens:
         if text.startswith(word, start):
            counts[start + len(word)] += counts[start]
   return counts[-1]
```

**Check:** `"aaa"` with `["a","aa","a"]` has three parses: `["a","a","a"]`, `["a","aa"]` and `["aa","a"]`.
Empty text has one empty parse.
The helper removes empty tokens and deduplicates and sorts the rest.
Integer additions may become more expensive as parse counts grow.

**Use when:** Multiplicity, rather than existence or one witness, is required.

### Transfer Check

What happens if counting permits arbitrarily many empty tokens?

### Answer

Any existing parse can receive unlimited empty tokens, creating infinitely many token sequences.
Exclude them or explicitly bound token count.
